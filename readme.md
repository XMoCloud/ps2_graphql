# PS2 GraphQL
## Local development

Run `npm run dev`, then open the local URL printed by Vite. The root route contains the real Reboot01 login. The four account menus are Overview, Projects, Audits and Skills. Projects opens 3D memory cards for the module and enrolled piscines, with quest browsers and individual save details. Development-only `/preview/dashboard` uses labeled sample records. Preview routes and sample records are excluded from the production build.

Memory cards float and slowly turn on hover. Opening a card uses the recorded 1.7-second black fade in each direction, followed by “Now Loading...” and saves appearing at 250 ms intervals. The darker gray browser has clickable Back and page controls, with arrow-key/Enter selection and Escape/Backspace return. Detail icons rise into place and spin; each detail background shares its icon's hue. Project details include account-scoped team members, captains, language, team dates and the latest grade. The detail Back button stays fixed at the bottom-left while information scrolls. System reduced-motion preferences shorten the sequence and stop continuous model animations.

Live PlayCanvas 3D is the default: startup glass and sound, blue smoke and login pillars, then the purple crystal world. The interface uses transparent charcoal panels, silver borders, cyan selection and interactive Recharts graphs. Account-scoped, paginated queries load progression, results, event levels, skill history and given/received audits. The persistent world stops rendering behind the full-screen memory browser. Logout returns through the camera transition directly to login; startup plays only on initial entry. Rejected credentials retain the login form and change the animated background to red smoke and glass cubes.

Overview counts graded project attempts, including failures before a later pass, and shows a separate project total deduplicated by name. Ungraded projects are excluded from pass/fail results. Passing piscine roots and recorded skills have their own summaries. User Distribution compares levels/audit ratios with an explicit all-students/my-cohort filter derived from module enrollments and cohort metadata. Projects XP includes signed corrections, decimal display values and exact XP totals/tooltips. Audits separates monthly credits, contribution balance and review outcomes. Skills shows every recorded skill in an interactive constellation, with selected-skill details and a timeline or single-date snapshot. Memory cards start their six-second hover turn from the resting angle and return smoothly when un-hovered. Their six-face mesh renders into a single canvas to avoid CSS 3D flashes; white language/school marks appear on the rear. Decorative status-page control prompts are removed, and the 404 shows only its number and return button. See [status verification and captures](docs/PS2_STATUS_REVIEW.md).

In the development server, open `/preview/startup` for synchronized playback, scrubbing, an overlay comparison, and cube wireframes against the original startup recording.

See [the rendering notes](docs/PS2_STARTUP_RECONSTRUCTION.md) and [asset credits](docs/PS2_ASSETS.md) for implementation, browser support and licenses. Run `npm run build` and `npm test` for the production build and automated checks.

Waves ambience starts immediately after successful authentication, before the camera transition, at its normal configured volume without an initial fade. Entering a memory card fades it to silence over 1.7 seconds and pauses the MP3; leaving the card fades it back in from the paused playback position. The UI uses outlined menu labels, thicker panel frames and sapphire/violet chart colors. Login includes distant, hazed short pillars around the main lattice, and the purple smoke continuously advects toward the viewer.

Login ambience uses the supplied `ps2_login_ambient.mp3`, streamed and prepared during startup. It starts fading in as the startup-to-login animation begins, loops on login, and fades to a paused state for rejected credentials or successful sign-in. The death ambience crossfades with it. Logout fades dashboard waves out and resumes the login track from its paused position during the incoming login camera. These scene fades take one second; refreshing the page resets the login track. The initial startup prompt has only Start system, with no sound toggle.

The account controls share a centered, responsive glass-blurred top bar: branding and date on the left, tabs in the center, clock and username/logout on the right, within a maximum width of 1520 px. Header and login sound toggles are removed. Hover feedback is blue, selection is yellow, and the larger gray date/time labels have black outlines. Branding and username use the same gray as date/time labels. Main labels use the locally hosted Helvetica Medium face with bold emphasis; logout is blue text without a box. Startup uses its previous fade-to-black ending before the login camera reveals the fixed pillar lattice. Memory slots are ordered Main projects, Go, JavaScript, Rust. Project and quest details omit Save location. Refresh data and Skip startup controls are removed from the normal interface. See [header screenshots and startup notes](docs/PS2_HEADER_REVIEW.md).

The fixed purple PlayStation button at the bottom-right opens About. It keeps the existing camera and full-size crystal ring in place while five independently tumbling foreground glass cubes in the reference arrangement appear, alongside an introduction, the creator's osu! web link and a Discord handle that can be copied. Purple smoke retains its normal brightness. Cubes grow over 600 ms, then shrink over 450 ms, with matching text fades, before Back, Backspace or Escape returns to the originating account menu. Transitions use a 60 fps update window; idle rendering remains capped at 30 fps. The existing renderer and scene clock are shared throughout. About glass refracts the complete animated background through both cube faces and uses the crystals' HDR environment plus the seven live orbital lights for reflections. Refraction targets are retained between visits, while the color-copy pass is paused in ordinary account menus. See [About and typography verification](docs/PS2_ABOUT_REVIEW.md).

Login uses an opaque black panel, a solid PlayStation-blue button and a single input focus frame with hover/click sounds. Rejected credentials turn the controls red and reveal the same brighter red smoke and two glass cubes used by the 404 scene. The normalized death ambience loops until the error clears. The supplied post-startup cue plays once at the start of the startup-to-login transition, without replaying on logout. See [login and error-scene verification](docs/PS2_LOGIN_ERROR_REVIEW.md).

Short distant pillars have opaque surfaces and write depth, so they correctly occlude other geometry. Their subdued appearance comes from reflected light and moving blue haze in the color shader, rather than surface transparency. The memory-card sound fade/pause/resume behavior is unchanged.

## Production source cleanup

Install with `npm ci`, test with `npm test`, and build with `npm run build`. Vercel uses the Vite preset and `dist` output. Generated dependencies, builds, local captures, reference archives, environment files and Vercel local state are Git-ignored. `node_modules` is no longer tracked; its local installation is retained.

Only active PlayCanvas/UI dependencies remain. Original fallback footage, active fonts, sounds, textures and license notices are retained. Unused legacy components, the Three.js prototype and duplicate assets were removed. Reference recordings and source assets are preserved locally in `.references/`, outside `public/`. Tests, asset credits, development tools and design documentation remain in the repository without being published as runtime assets.
